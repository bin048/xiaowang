# 接力改动与验收说明（2026-11-08）

继 M1.1 Mac 调试版之后的最小改动，不重搭主应用，不新增人物库，不改 Windows 交接包。
改动前源码已备份到 `备份/20261108_接力_改动前/`（含 app.js、processing.js、presets-ui.js、delivery-ui.js、main.js、构建产物、上一版测试结果）。

## 一、这轮改了什么

1. **“设置三个人物位…”一步到位**（`Electron悬浮入口/main.js`、`源码/delivery-ui.js`、`源码/presets-ui.js`、`源码/app.js`）
   - 悬浮球菜单该项打开页面时附带 `&xw_open=presets`。
   - 页面识别后自动切到“信息渡口”，展开人物预设并滚动到可见位置、聚焦标题。
   - 现在该项是“设置三个人物位…（在小王页面直接定位）”；未配置的人物位菜单文字改为“未配置，点‘设置三个人物位…’”。
   - 仍用系统默认浏览器打开同一 `127.0.0.1` 地址，不接管、不读取任何浏览器资料。

2. **跨浏览器数据边界提示**（`源码/presets-ui.js`）
   - 若本地服务里已保存的 `receiver_id` 与当前浏览器的接收器不一致（换过浏览器或清过站点数据），面板顶部直接说明“不是同一份浏览器资料”。
   - 此时点保存会先弹确认，取消则完全不动原配置，避免误把另一浏览器的人物库当成同一套。

3. **画像中断自动恢复 + 跨标签页只算一次**（`源码/presets-ui.js`）
   - 画像任务仍用 `navigator.locks` 按事件加锁。
   - 新增：每次调度前用 `navigator.locks.query()` 查该事件的锁是否有人持有。没人持有却停在“生成中”的，判为上次页签被关掉，自动重新排队；有锁则不动，避免重复调用模型。
   - 手动“重新生成画像”按钮保留。

4. **未自动归档的原因显示为可操作清单**（`源码/processing.js`、`源码/presets-ui.js`）
   - 新增 `presetIssue`：人物已删除、正文提取失败/部分提取、来源归属已变、另一浏览器的投递等，逐条显示**文件名 + 原因**，并给“停止自动重试并保留在渡口”按钮。
   - 点该按钮会用原接收凭据补一条 ACK，投递退出队列不再每 2 秒重试；**资料仍留在信息渡口、归属仍为空**，可手动选择人物，不会改投给别人。
   - 单份异常只影响它自己，其他投递照常归档与生成画像。

5. **两个标签页并发时自愈**（`源码/delivery-ui.js`、`源码/processing.js`）
   - 两个标签页同时轮询同一份投递时，后写入的一方会因乐观校验拿到“其他窗口已更新资料，请刷新后继续”。
   - 以前这种情况会一直重复报错、页面内存视图永久落后；现在会自动重新载入本地资料再重试这份投递，不必手工刷新。
   - 复测：该用例此前 4 次里偶发失败 1 次，加上自愈后连续 5 次 8/8 通过。

## 二、怎么启动与验收

服务若已在运行（8915），改动已生效（页面每次请求都重新读取 HTML）。

```
双击 打开小王.command        # 会拉起服务、悬浮球并打开已配对页面
```

- 悬浮球菜单 → **设置三个人物位…（在小王页面直接定位）**，应直接落到信息渡口的人物预设且已展开。
- 三个槽位按需选择后保存；不选也是普通模式，不影响现有流程。
- 快捷自查：页面控制台 `__xw.view()` 应为 `intake`，`document.getElementById('person-presets').open` 应为 `true`。

## 四、限制与未测项（不夸大）

- **模型仍是模拟接口**：没有真实调用外部 API，也没有产生费用。画像成功/失败/换模型重试的链路是用本地桩验证的，不代表真实模型输出质量。
- **`--no-sandbox` 只用于测试进程**：本机从受限会话启动时 Chromium 自身沙箱初始化失败（`sandbox initialization failed`），因此测试脚本通过 `XW_TEST_NO_SANDBOX=1` 追加该开关；产品代码、`webPreferences.sandbox:true` 均未改动。从 Finder/Terminal 正常双击启动不需要它。
- **两个标签页并发的偶发失败未彻底归零**：改动前出现过 1 次“同一份投递两个页签都报窗口冲突、停在待投递”，已加自动重载；连跑 5 次未再复现，但未证明根因已消除。真遇到时刷新任一页签即可，投递与原件都在服务队列里，不会丢、也不会重复生成画像。
- **原生菜单点击没有自动化**：改为对 `h5Url('presets')` 的地址断言 + H5 侧深链用例；`XWEntryTest.h5Url` 已暴露给测试。
- 三个槽位仍未配置、该浏览器的模型密钥仍未配置，留给用户自行选择；本次没有读取或迁移任何浏览器业务资料、运行队列或密钥。
- 真实微信采集、Windows 主线均未触碰。
