# 「小王语料」App 融合说明（2026-11-08）

把 M1.1（当前开发版）的界面与能力融合进 `/Applications/小王语料.app`，保留 App 外壳、签名身份与已有语料。

## 结论先说

- **语料没动**：App 与本项目的页面使用同一个存储键 `xiaowang-ui-v02-20261025`。实测 4 个人物（1 个本地真实人物 + 3 个演示人物，共 65 条事实与语料）完整读出，`selected` 也保留。
- **原生能力保留**：微信/文件转入（`nativeService`、`listImports`/`markImport`）、原生保存导出（`saveExport`）在新页面里仍在。
- **悬浮球可以接进来**：App 内的页面现在能直连本地投递服务（8915），拖进悬浮球的资料会直接进 App。

## 改了什么

| 位置 | 改动 |
|---|---|
| `App/Contents/Resources/index.html` | 换成 `小王M1.1_应用内版.html`（由 `源码/build.py --app` 生成） |
| `App/Contents/Resources/index_v0.7.1_备份.html` | 旧页面留档，随时可换回 |
| `App/Contents/Info.plist` | 版本号 `0.7.1` → `1.1.0` |
| `源码/delivery-ui.js` | 新增 `NATIVE` 运行期识别：App 内没有投递服务时显示「本机资料入口」，有直连令牌时显示服务入口并保留悬浮球控制、人物位 |
| `源码/build.py` | 新增 `--app` 构建；预置 `XW_APP_ORIGIN` 与空令牌占位，由安装脚本注入 |
| `Windows本地服务/本地投递服务.py` | 新增 `app` 角色令牌（重启后沿用）+ 仅对 `Origin: null` 放行的 CORS 与预检 |
| `安装融合版.command` | 一键：注入令牌 → 重签名 → 替换 /Applications → 启动 |

## 安全模型（app 令牌）

- `app` 令牌与 h5/desktop 分离，只有它能接受 `Origin: null`（本机 `file://` 页面）。
- 普通浏览器角色不受影响：`h5` + `Origin: null` 仍返回 **403**（原有安全测试保持通过）。
- `app` 令牌只在 `Origin: null` 时可用；带其它来源一律 403。
- 令牌写在 `本机配对.json`（0600），重启沿用；执行「撤销本机配对」后失效，需重装 App 才能再连。

实测（测试服务 18915 端口）：

| 场景 | 结果 |
|---|---|
| app 令牌 + Origin: null | 200，响应带 `Access-Control-Allow-Origin: null` |
| OPTIONS 预检 | 204，允许 `Authorization,Content-Type,X-XW-Features` |
| h5 令牌 + Origin: null | 403（不放宽） |
| app 令牌 + 外部来源 | 403 |
| 无令牌 | 401 |

页面侧（真实 `file://` 打开）：状态显示「本机入口已连接」，悬浮球开关、人物位、暂停接收都在；无 JS 报错。

## 怎么装

1. 双击 `打开小王.command`（重启本地服务，新代码会生成 App 直连令牌）
2. 双击 `安装融合版.command`（注入令牌 → 重签名 → 替换 App → 自动打开）

安装时旧版会被移到废纸篓，文件名 `小王语料_旧版_<时间>.app`，随时可以拖回来还原。

## 会退一步的地方

- **服务没跑时**：App 里那块显示「本机入口未连接」，其余本地功能（语料、画像、事项）照常；启动服务后自动变为已连接。
- **令牌撤销后**：`撤销本机配对` 会让 App 断开，需要重跑一次安装脚本重新注入。
- **App 只读本地服务**：不改变任何云端行为，数据仍只在本机。

## 回退

- 单步回退页面：把 `Contents/Resources/index_v0.7.1_备份.html` 改名回 `index.html`，再 `codesign --force --sign - --options runtime` 重签。
- 整体回退：废纸篓里的旧包，或 `备份/20261108_语料App融合/小王语料_v0.7.1_覆盖前.app`。

## 入口统一：打开小王 = 打开小王语料 App（2026-11-08）

以前「打开小王」是 `shell.openExternal` 打开浏览器里的 `http://127.0.0.1:8915/小王.html`，
现在改为**优先启动本机安装的「小王语料」App**，浏览器页面只在没装 App 时兜底：

| 入口 | 现在打开什么 |
| --- | --- |
| 悬浮球菜单「打开小王（小王语料 App）」 | `/Applications/小王语料.app` |
| 托盘菜单「打开小王（小王语料 App）」 | 同上 |
| 悬浮球菜单「设置三个人物位…」 | 同上（App 页面顶部的「人物预设」面板就是定位位置） |
| `打开小王.command` | 先起服务 → 拉起悬浮球 → 再打开 App |

实现要点（`Electron悬浮入口/main.js`）：

- `appBundle()` 依次找 `XW_APP_BUNDLE` 环境变量 → `/Applications/小王语料.app` → `~/Applications/小王语料.app`；
  找到就用 `open -a <bundle>` 启动（已在运行则直接切到前台，不会开第二个实例）。
- `launchApp()` 失败（没装 App / 非 macOS）时才 `shell.openExternal(h5Url())`，地址与原来的配对页完全一致。
- 因为没有安装 App 的场景仍在（比如只在开发目录里跑），这条兜底保留了 `#xw_pair=<h5>` 与 `&xw_open=presets`。

`运行Mac版.py` 同步改为：拉起悬浮球后**先 open App**，App 不存在才开浏览器；
并新增「悬浮球没上线就自动重启一次入口」——上一次悬浮球异常残留会占住单实例锁，
新进程会秒退，这时脚本会写 `停止悬浮.flag` 结束旧进程再重新拉起，避免出现「点了打开小王却什么都没有」。
