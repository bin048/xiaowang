# Windows 真机验收步骤与回传

状态：本包已在一台 Windows 11 真机完成基础链路验收，结果见主报告及 Windows真机证据。以下为重复验收操作说明，不代表 Windows 10 已验证。请在 Windows 10/11 的真实交互桌面运行，只使用本目录虚构资料。不要使用已有个人浏览器资料或正式聊天数据。

## 准备与启动

1. 解压到本机普通可写目录，保留完整结构。准备 Python 3.10+、Node.js 22.12+。Electron 依赖按根目录「安装悬浮依赖.cmd」准备（需要下载固定版本 Electron）。没有附带预编译 Windows exe；依赖未准备时不视为启动通过。
2. 在 Edge/Chrome 新建一个仅用于本次虚构验收的浏览器资料环境。在默认浏览器中完成相同隔离设置，避免一键打开落入正式工作资料环境。记录 Windows 版本、浏览器版本、显示器数量、缩放比例、Node/Python 版本。
3. 双击「开始Windows虚构验收.cmd」。它复用现有一键启动器，数据仅存本目录「运行数据」，端口18925。通用「一键启动.cmd」使用另一个默认数据目录，本次不要混用。
4. 确认本机服务终端、独立桌面悬浮球、已配对 H5 均出现。H5 仍为一个 HTML。运行「记录_started.cmd」，截取服务启动、桌面悬浮球及 H5 信息渡口。
5. 本目录「运行Windows自动检查.cmd」运行 SQLite 资源、服务协议、入口恢复测试。自动检查不是物理拖拽或桌面验收，仍须逐项操作下表。

## 桌面、收件和恢复

把结果和证据文件名填入「Windows真机验收结果表.csv」，只将实际完成的项目填 PASS；失败填 FAIL，未做填 NOT_RUN。

| 编号 | 操作 | 必须观察的结果与证据 |
|---|---|---|
| W01 | 一键启动 | 三组件真实出现，保存环境信息与启动截图 |
| W02 | 鼠标拖动球、菜单隐藏、托盘唤回 | 位置变化，隐藏后托盘能唤回。H5显示/隐藏和找回也要各点一次 |
| W03 | 从资源管理器分别物理拖入「虚构资料.txt」「虚构资料.docx」「虚构资料.pdf」 | 不得用文件选择器代替拖入；建议录屏覆盖资源管理器拖至悬浮球、H5收件、正文及来源。TXT/DOCX应有正文；PDF可为部分提取但必须如实标示，保留原始文件 |
| W04 | 菜单投递一段“【虚构】Windows桌面文本验收” | H5信息渡口出现原文、独立事件ID及来源 |
| W05 | 关闭全部 H5 标签后投递虚构文本 | 球显示等待小王接收，不能提前成功；运行记录_queued.cmd，截图 |
| W06 | 从球菜单打开小王 | H5保存后球才显示成功；运行记录_received.cmd；展开来源与接收凭据并截图 |
| W07 | 关闭再重开 H5 / 浏览器 | 原正文、来源事件ID、回执仍在，资料数量不变。不要清空浏览器资料 |
| W08 | 运行仅停验收服务.cmd，保持球运行，再投递一段虚构文本及一个文件 | 球明确等待/失败、资料不丢；记录_service-stopped.cmd。再次开始验收，待投递按原事件ID恢复，H5接收后记录_restarted.cmd |
| W09 | 在Windows终端执行 `py -3 同事件重试与未授权验证.py`（工作目录为本目录） | 同一事件重复3次后SQLite数量不变；H5刷新后来源数量也不增加，回执及source_record_id不变。脚本无法代替H5核对 |
| W10 | 两次从球主动发送完全相同的虚构正文 | H5保留两个独立来源事件ID，不合并。可在两条收件记录展开凭据截图 |
| W11 | 服务在线时双击未授权网页测试.html，点击测试；结合W09日志 | 该网页不能读取正文或触发抓取；截图网页结果和已配对H5在线状态。不要把服务离线造成的失败当成安全通过 |
| W12 | 退出悬浮入口，确认它停止；服务可按设计独立保留 | 记录进程状态：只退出入口并不关闭服务。随后重新开始，再运行结束Windows虚构验收.cmd，等5秒，运行记录_all-stopped.cmd | 
| W13 | 核对关闭全部后的进程 | 只允许本次证据采集脚本、其PowerShell子进程和手动打开的终端/浏览器。测试包范围的Electron、Node启动器、投递服务应退出；发现残留填FAIL，不自动强杀其他应用 |
| W14 | 无服务状态下使用H5手动粘贴与文件上传 | 原功能可保存；六大导航、人物、画像、事项、模型设置界面仍存在。不要填写真实模型密钥 |

采集脚本只读本验收包路径匹配的进程和本目录SQLite/待投递摘要，不输出配对令牌或聊天正文。`package_processes` 中采集脚本自身PID、其父终端和子PowerShell可保留；其余组件要逐一核对。只记录本包能匹配到的进程，不能据此宣称整个Windows系统无其他Python/Electron。

## Windows 浏览器迁移与回退（W15）

1. 在新的隔离浏览器资料环境，双击「源码/M1.0基线.html」。它是本次迁移测试的旧M1.0单HTML；不要打开任何正式个人资料文件。
2. 在信息渡口「资料检索、纠错与完整备份 → 恢复完整备份」选择「Windows真机证据/迁移测试/旧版file完整备份_虚构.json」。这只用于给隔离旧版准备固定虚构样本。核对人物11、语料46、来源2、事项1（以数量与关联校验.json为准）。
3. 在旧版点「完整备份（升级前）」实际下载，保留下载文件，关闭旧版。不要只使用“人物库导出数据”，那不含渡口事项。
4. 打开已配对HTTP版，先导出当前完整备份，再用现有「恢复完整备份」选择上一步下载。核对数量、人物ID、来源ID、事项personIds/linkedSources/sourceId、语料originRef；下载HTTP恢复后的完整备份对比。不得靠浏览器跨源自动共享数据。
5. 在HTTP版增加一份虚构语料和关联事项，再导出完整备份。用另一个新的隔离浏览器资料环境打开同一「M1.0基线.html」，恢复HTTP导出文件，核对旧资料及新增资料均在；关闭、重开后再查。
6. 返回最初旧版的原浏览器资料环境，确认原file资料仍在；迁移采用复制备份恢复，不删除原环境。保留全部JSON、核对表及截图。
7. 本步骤证明M1.0完整备份互通。更早原B的“人物主库导出”与“渡口导出”是两份旧格式，本包不把单库JSON称作完整迁移；若要迁移更早原B，需另行用虚构样本验证其双备份转换。模型密钥、原始文件二进制、Electron待投递目录不在H5完整备份中，不能声称它们一起迁移。
